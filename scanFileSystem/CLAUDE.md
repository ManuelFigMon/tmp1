# CLAUDE.md — working notes for `scanFileSystem`

Guidance for agents (and humans) changing this code.

## Non-negotiables

1. **Unattended-safe.** This runs under Windows Task Scheduler with no console.
   Never add `input()`, `getpass`, a progress bar that expects a TTY, or
   anything that can block waiting for a human.
2. **stdout stays clean; logs go to stderr.** Use `log_info` / `log_warn` /
   `log_error`. Never `print()` to stdout.
3. **Exit codes are the contract.** `0` success, `2` config error, `3` I/O
   error. Task Scheduler and the SAS `SYSTASK` wrapper both branch on these —
   never swallow a failure into a `0`.
4. **Windows-safe paths.** Use `pathlib`, raw strings for UNC literals
   (`r"\\server\share"`), and compare paths case-insensitively with
   `normalize_path_text()`. Never assume `/` separators or a case-sensitive
   filesystem.
5. **No secrets, no network.** The scanner reads the local/UNC filesystem only.
   Don't add API calls, telemetry, or credentials.
6. **Keep the dependency surface tiny (v1.3.3).** CSV output must stay pure
   standard library; XLSX may use `openpyxl`/`xlsxwriter` only, imported lazily
   inside the writer. **Do not reintroduce pandas or numpy** — a broken pandas
   install caused a hard failure in the field, and this code is headed for
   `cgs_ai`, which must run stdlib-only inside Snowflake. The tests are
   pandas-free too (stdlib `csv` + `openpyxl` for read-back).

## Architecture — keep the three layers separate

| Layer | Functions |
|---|---|
| Crawl / filter / metadata | `iter_candidate_files`, `is_folder_excluded`, `parse_boundary`, `stat_times` |
| Keyword extraction | `extract_keywords`, `keyword_columns`, `keyword_slug` |
| Metric profiles | `MetricProfile`, `RegexStepProfile`, `METRIC_PROFILES`, `aggregate_steps` |

**A new log format must not require touching crawl or output code.** Add a
`RegexStepProfile` entry to `METRIC_PROFILES` instead. If you find yourself
editing `scan()` to support a format, the profile interface is the thing to
extend.

## Conventions

- CONFIG block at the top holds every default; each has a matching kebab-case
  CLI flag. CLI overrides CONFIG (`resolve_settings`).
- List params accept a single string, a semicolon-delimited string (how SAS
  passes them), or a real list — normalize through `_as_list`.
- Validation happens in `validate()` **before** any crawling, so a bad config
  fails fast and cheap.
- Per-file errors are annotated in `parse_status` and the scan continues; only
  config and output failures are fatal.
- `folder_exclusion_list` defaults to **empty** (v1.3.1). Excluding by default
  would silently drop data — don't reintroduce defaults here.
- `output_file_path` is **optional** (v1.3.2). `input_folder_root` is the only
  required parameter. Both auto-generated names (no path given, or a directory
  given) come from the single helper `default_output_name()` —
  `scan_YYYYMMDD_HHMMSS.csv`. Keep them going through that one function so the
  naming rule stays in one place.

## Tests

```bash
pytest -q          # 42 checks, ~0.6s, no network
```

Fixtures are generated by `tests/make_fixtures.py` (idempotent). The
hand-summed timing expectations live in that module's docstring and in
`EXPECTED` in the test module — if you change a fixture's timing block, update
both.

Fixture tree deliberately includes edge cases: `Old/` + `Test/` (exclusions),
`Older/` (near-miss that must survive excluding `Old`), nested subfolder,
clock-format durations (`1:03.05`), varied mtimes for the date filter, invalid
UTF-8 bytes (latin-1 fallback), a broken symlink (non-OK `parse_status`), and a
`.dat` file that must never appear in output.

The broken-symlink fixture is skipped automatically where symlinks aren't
available (e.g. Windows without privileges) — keep that guard.

## Gotchas

- `pandas.read_csv` turns empty strings into `NaN`; tests use
  `keep_default_na=False` when asserting on text columns.
- Excel engine chain is `openpyxl → xlsxwriter → CSV fallback`. Don't hard-code
  an engine.
- Duration parsing must keep handling both plain seconds and `h:mm:ss` /
  `mm:ss`; SAS switches formats once a step exceeds a minute.
